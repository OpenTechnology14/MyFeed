# Connection configuration matrix

Baseline: 2026-10-04; reconciled 2026-10-08. **Required direction: all posts, alerts, and features go through Connections first to configure.** Existing setup, local editing, default AI Pipeline, API/YouTube sources and manual Rocket.Chat/Mastodon-compatible posting are implemented locally. TikTok remains unsupported. Build/mock evidence and authenticated/paid/publishing provider proof remain separate.

The intended sequence is **Connections → configure the source or capability → validate readiness → link/select the feed → customize its behavior → use it in the reader**. Reader actions can lead back to the owning connection, retaining the selected feed/item. Saving configuration does not authorize publishing, delivery, or paid generation. Initial source collection remains a visible, read-only action.

Connections is the common setup entry point. Storage scope remains explicit: sources own collected items and sync; feeds own lenses, display preferences, and mention handles; AI currently has workspace configuration. Local features need no invented provider account or credential. Profile remains local; theme changes use the rail/header button, with no Appearance section in Settings. The five-feed and three-linked-source limits remain unchanged, including paused sources. Any future destination/processing connection model and capacity policy must be specified before implementation; grouping setup in Connections alone does not change limits.

Posting implemented locally 2026-10-08 under PROP-033–035: configure an independently encrypted writer, read-only check identity/destination, save local drafts, review exact account/room/audience/body and explicitly Send. Reading/sync stays read-only. Pausing blocks sends; source repair disables writing; disconnect removes drafts/keys while preserving outcome metadata. Additional providers stay independently scoped under PROP-020. No live publishing was tested.

## Editing boundary

PROP-028 implements a local title/body override, visibly marked as edited, with Show original and Reset local edits. Collected provider content, external identity, author, timestamps, warning/media metadata, and thread membership retain provenance. Feed eligibility, deduplication, ranking, mention detection, and digest inputs continue to use collected originals unless a later explicit specification changes that policy. An alert is derived from its source item; it is not an independently editable notification. No remote post, email, or chat is changed.

Repeated ingestion updates the collected version without erasing the separate local override or saved/read state. Unlink/feed deletion preserves connection-owned data; connection removal deletes the associated overrides. Backup/restore, stale drafts, reset after a new source version, and changes visible across linked feeds are covered by isolated API/backup/browser fixtures; authenticated provider evidence remains separate.
