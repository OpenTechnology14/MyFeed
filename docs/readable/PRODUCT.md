# MyFeed product behavior

The workspace starts with one empty feed. Adding the first connection is the primary onboarding action. Connections own their collected data and can exist before feed assignment. A connection can supply multiple feeds; up to three may contribute to the same feed. At most five feeds may exist. Paused sources count toward the connection limit. The last feed cannot be deleted.

## Reading and background data

Reading puts the collected content first, in a social timeline. All sources and content types share one mixed timeline, with visible gaps between entries. Feed names and customization rules distinguish feeds; no type tabs, source dropdown, or sort caption appear in the reader. The top row contains “The latest from your world”, Saved, Unread, Alerts, and Refresh feed. Refresh feed is no longer in the sidebar. Posts lead with the author, handle, paragraph-preserving message, and image attachments with source alt text. Articles and email retain title/excerpt previews and collected-text dialogs. Mastodon content warnings hide the body and media until explicitly revealed. Filtering explanations are available through item details and Customize filters → Filter results, so they do not compete with the content.

Chats appear as conversation previews in the mixed timeline. Opening a preview shows its eligible messages chronologically; Back to feed returns to the timeline. Groups are scoped to the connection, room, and thread; reply metadata joins a root to its replies. Only messages eligible under the current feed rules, query/unread filters, or saved lens enter a group. Excluded roots or neighboring messages are never pulled back in. Counts describe collected messages, not complete remote history. On mobile, a selected conversation fills the view, with a back button to the list. Messages can be bookmarked or marked read individually; this reader does not send chat replies.

The reader supports query/unread filters, read markers, and bookmarks. Search also matches author handles and channel names. Saved updates and messages remain available even when feed rules later exclude them. Source links open externally. The optional Sample library contains six articles, two posts, and five chat messages in two conversations; all are fictional and labeled.

The data flow is **connection → collected data → linked feeds → each feed’s filters → feed view**. Connection data is inspected before filters. Each connection has a Post log button that expands a section on the same page, closed by default, containing only that connection’s collected items. Items inside the log expand to show their text and Save/Unsave action. Linked feeds and Activity remain available alongside the expandable log. The same item has one local saved/read state across feeds. Saved items remain available through the reader’s Saved filter while their source is linked, and through the connection’s Saved filter even after all feeds are unlinked.

Feed customization edits name/color/description, context, include/mute rules, deduplication, sort, layout, per-item text limits and type overrides, media visibility/size, font size, line spacing, reading width, and conversation preview count. Unsaved customization/profile drafts remain in session memory across navigation, with explicit Discard and an unload warning. Background sync belongs to the connection, not the feed. Linking/unlinking applies immediately; filter edits use Save customization.

## Filtering contract

Filtering checks enabled source ownership first, then mute keywords, then include keywords, then duplicate detection. Mute wins over include. Include matches **any** configured keyword, case-insensitively, across title, content, author, and tags. Empty include rules accept all otherwise-eligible items. Context is scored by matching unique words of three or more characters; selecting relevance sort brings higher scores forward. It is deterministic keyword ranking, not semantic inference.

Duplicate links remove tracking parameters and fragments. Ordinary entries without links deduplicate by normalized title/content. Chat events use connection plus provider message ID instead, so repeated short messages and equal text from different participants or rooms remain distinct. Duplicate detection affects the feed lens, not raw storage. Source ingestion deduplicates by connection plus provider item ID, preserves the original local ID and saved/read state, and retains the newest 300 ordinary entries per connection plus any older saved items.

Manual sync coalesces requests per connection, including simultaneous refreshes from different feeds. Healthy sources finish even when another source fails. Background sync is off by default per connection and checks opted-in enabled sources every five minutes while the API process runs. The browser refreshes workspace state every 15 seconds. Background work continues while the page is closed if the local process remains running.

## Local mention alerts

Customization stores an alert enable switch and up to 20 explicit @handles per feed. Defaults are off/empty for new and older feeds. The Alerts button opens condensed excerpts of included collected items mentioning a complete configured handle, case-insensitively. Feed rules and paused-source exclusions apply; saved/search/unread reader filters do not hide the alert inbox. Its badge counts unread matching items. Opening a tagged post marks it read and preserves content-warning reveal behavior. Empty/unconfigured states provide a Connections setup path, then selected-feed customization.

Mention detection reads normalized title/body text; it does not infer identities from author names, email, or profile information and does not query provider-native notification APIs. Excerpts use up to 180 Unicode code points plus an ellipsis and do not run AI. External alert delivery through connections is proposed in PROP-026 and is not implemented.

## Settings, AI, and removal

The local profile contains a display name, optional profile email, and light/dark/system appearance. Profile email does not connect a mailbox. AI has a separate workspace-level key and model and does not consume a source connection slot; it is a processing stage. Digests are requested manually and use the current included lens, up to 20 items, and context. Each digest is a dated snapshot with model and numbered source references. A snapshot is hidden if its rules change or any referenced item is filtered out. Disconnecting a source clears the feed's digest; in-flight generation cannot restore a digest referencing removed entries.

Disconnecting a source deletes its local credential and entries. Deleting a feed removes its links, digest, and feed receipts while keeping connections, collected items, saved/read state, and connection receipts. These operations require an explicit remove action in a dialog and leave external accounts unchanged. Pausing keeps collected data. Atomic store writes and stale-edit detection prevent silent overwrites. This edition does not offer hosted accounts, shared workspaces, account posting, or automatic AI calls.

## Connection-first setup and item editing

Connections is the common setup entry for source posts/articles/email/chats, local mention alerts and manual AI. Select a target feed, inspect actual readiness, configure downstream controls and return to that feed. Mention handles remain feed-owned; AI remains workspace-owned with compatible Settings links. Local features and AI do not consume the three-source capacity. Saving configuration never makes a paid AI call or sends an outbound message.

Connections → Post log → Edit local copy stores revisioned title/body overlays, displays an edited indicator and offers Show original, Cancel, Save and explicit Reset confirmation. The title must be nonblank and at most 500 UTF-16 units; body can be empty and is bounded to 100,000 UTF-16 units. Unicode is preserved. Provider originals, identities, metadata and read/save flags remain intact. One override appears across all linked feeds; repeated ingestion updates the original without removing the overlay. Stale edits fail visibly. Filtering, mention detection, ranking and digest inputs use originals. Removing the owning source deletes its items/overlays; removing a feed preserves them.

## Requested connection extensions — 2026-10-05

Implemented on 2026-10-08: AI Pipeline's default digest profile (PROP-029), a separate API source (PROP-030), and bounded public YouTube metadata source (PROP-031). In Connections, select the input feed, open Configure pipeline profile to save processing instructions, then Review AI Pipeline to inspect originals/context/exact instructions and confirm token/budget-bounded generation. Output is the dated generated digest snapshot in that feed; it never becomes a collected input. Workspace AI key/model setup remains compatible. Processing uses no source slot. Importing externally generated JSON uses an API source and consumes a source slot. A YouTube connection uses a user-owned encrypted API key and a public channel upload list or public/explicit-Shorts playlist; it stores metadata/link/thumbnail/duration only, never playback/transcripts or personalized/private/account data. Under-four-minute videos are candidates, not exact Shorts. TikTok remains unimplemented under PROP-032; arbitrary model endpoints/chains and automatic processing are not included.

API source setup maps public HTTPS JSON GET responses into post/article/email items. Configure root-array or dotted item paths, mandatory stable IDs, optional text/link/image/tags mappings, no/bearer/X-prefixed API-key authentication, and optional cursor path/query parameter. Collection reads up to three 100-item pages; Load older source items resumes the returned cursor. Missing dates use 1970-01-01, while invalid supplied dates fail. Mapping/auth-mode changes require an explicit collected-data reset; credential replacement alone retains items. A failed/malformed later page does not commit a partial batch. API imports preserve source ownership, limits and saved/read/local-edit state. Provider-specific permissions, quotas and OAuth are not bypassed. See [Integrations](INTEGRATIONS.md) and [the queue](PROPOSAL_WORK_QUEUE.md) for remaining YouTube/TikTok scope.

## Requested posting — 2026-10-08

Manual posting is implemented locally under PROP-033–035, with provider mocks and browser fixtures rather than live publishing evidence. On a Rocket.Chat or Mastodon-compatible connection, separately configure/check the writing token and identity, save a local text/link draft, review its exact sender/destination/audience/reply/body, then explicitly Send. Reading credentials and followed authors do not define the writer. Existing source slots stay unchanged. Rocket.Chat supports joined normal public channels/thread replies; Mastodon supports explicit unlisted/public/followers-only posts and public/unlisted-parent replies, with warnings/language and checked limits.

Up to 50 drafts and 100 outcome receipts are retained locally. Review expires after five minutes and is bound to draft/source/writer versions. Fresh identity and reply-target reads precede each send. Duplicate tokens never resend; ambiguous delivery stays Unknown without automatic retry, including after restart. Sent/unknown drafts cannot be overwritten/resubmitted. Source repair disables writing; pausing blocks it; disconnect removes drafts/keys but retains receipt metadata and cannot retract an already transmitted message. Global posting receipts remain visible in Connections after removal. Local draft removal never deletes a remote post.

Reader and Post log Reply shortcuts enter the source-owned composer; they do not restore excluded chat context. A manual digest-copy shortcut requires a current fingerprint/revision and fully eligible references on a bounded page; stale/unavailable snapshots are rejected. Drafts and returned send metadata never become collected originals automatically. Preview uses in-memory fictional setup/drafts and Simulate send, with no workspace/provider API calls or credential persistence.

Text/links and supported replies are the initial scope. Per-provider permissions, server limits and actual account evidence remain necessary; reading a public feed does not confer writing access. More providers are selected separately through PROP-020. Automated alert delivery stays PROP-026, and local item editing stays PROP-028. Generating an AI result or refreshing a feed never publishes content.

The app requests metadata/count summaries and loads retained items through revision-scoped pages of at most 50. Search, Saved, Unread, alerts and complete feed filtering apply before paging; changing data/query invalidates a cursor and offers reload. Conversation pages include only eligible messages, chronologically. Ordinary retention remains 300 per source plus saved items; reaching the provider's history end does not mean all remote history is retained.

Manual digest generation reviews included original excerpts/context, configured model, item/excerpt limits, token and output caps, and verified highest model rates before confirmation. The server counts exact input tokens first, reserves the maximum charge under those rates, then submits at the default service tier with no tools, storage or automatic retry. Uncertain outcomes keep the reservation and require review. Price bounds depend on rates the user verifies; they are not an account-wide billing limit. Configuration/rules/source changes can discard an in-flight result. No real paid-provider round trip is claimed.
