## Common checks

| ID      | Apply to                  | Required proof                                                                                                                     |
| ------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| API-U01 | Every route               | Allowed loopback Host; absent/allowed Origin; rejected external Host/Origin; no-store response                                     |
| API-U02 | POST/PUT/PATCH            | JSON content type, 1 MiB body bound, malformed and invalid inputs rejected without partial mutation                                |
| API-U03 | Resource routes           | Existing/missing/deleted IDs; correct ownership and feed links; no recreation of removed source work                               |
| API-U04 | Mutation routes           | Valid update, persistence/reload, repeat/concurrent request and documented conflict behavior                                       |
| API-U05 | Feed/profile edits        | Correct workspace revision accepted; stale revision gets 409 and leaves data unchanged                                             |
| API-U06 | Credential/provider paths | No plaintext/ciphertext credentials in public output/logs; timeout/error sanitization; no unintended paid call or outbound message |
| API-U07 | Sync/generation           | Success, empty, partial failure, paused/disconnected/config-changed state, retry and in-flight removal                             |
| API-U08 | Every fixture run         | Isolated temporary store/key; sanitized result record; cleanup proves user workspace untouched                                     |

These are required checks, not a claim that every route has every assertion. Local Host/Origin guards are not authentication; hosted role/tenant checks belong to PROP-022 and must exist before any public deployment.

Source deletion removes drafts and both credentials; metadata receipts remain, including late acknowledgments of already transmitted requests. Startup never replays Sending. Source repair disables writing and invalidates identity, while pause blocks Send. Network write redirects are rejected, and credential-bearing headers/query parameters cannot cross origins. Posting sends are an exception only to reading adapters, not authorization for background sync/AI/configuration to publish.

2026-10-08 extension of existing routes: API-003 persists `aiPipeline` profile/instructions with ordinary feed revision guards; API-017 returns exact processing instructions for review, and API-013 uses the identical instruction payload for token count/generation. API-005 accepts `kind: api` only with mapping configuration and valid auth/HTTPS setup, and `kind: youtube` only with a public target, bounded source mode and user-provided encrypted API key. API-006 treats API/YouTube source configuration changes as identity changes requiring explicit reset; blank secrets retain encrypted credentials. API-009/014/015 use bounded JSON and YouTube adapters with cursor progress. `tests/api-source.test.ts`, `tests/connectors.test.ts`, `tests/network.test.ts` and additional `tests/ai.test.ts` assertions cover mappings/bounds/IDs, public-video metadata/cursors, secret/restart/reset retention, credential-bearing redirect origins and reviewed instructions. No new route or paid/live account proof is inferred.
